# CLAUDE.md

Guidance for Claude Code (and other AI agents) working in this repo.

## Project

Two independent Python programs that grade a repository against a weighted
rubric and say which fix buys the most points. `gradebook-tests/` scores the test
suite; `gradebook-code/` scores the code it covers. Each is one module with a
console-script entry point, its own `pyproject.toml` and its own pytest suite;
they share these docs, the Makefile and a CI job, and nothing else.

**Standard library only, both of them.** `dependencies = []` in both
`pyproject.toml` files is a feature, not an oversight — these tools get pointed
at other people's repos, and an install that drags in a tree is a tool nobody
runs on a whim.

## Commands

```sh
make help        # every verb this repo exposes
make dev         # editable installs of both, plus pytest and ruff
make install     # pip install both
make test        # both suites
make test-tests  # just gradebook-tests
make test-code   # just gradebook-code
make lint        # ruff over both
make setup       # install the pre-commit hook
make check       # run all pre-commit checks on the whole tree
make clean       # caches and egg-info
```

Each tool also works alone: `cd gradebook-code && pytest -q`.

## Conventions

- **No evidence is not zero.** A dimension with nothing to measure — no git
  history, no interfaces, no inheritance — is left *unscored* and the remaining
  weights renormalise. Never score an absent signal as zero; it punishes a repo
  for what it does not have and silently sinks the number.
- **Weights add to 100** per tool, and `--list-dimensions` prints them. Changing
  a weight changes every published score, so it is a `feat!:`, not a tweak.
- **Every red flag carries `file:line`.** A score is not actionable; the flags
  are the product.
- **Read-only.** No config file, no build, no test run, no network. A pass over
  the working tree plus `git log` — keep it that way.
- **Generated and minified files are skipped, not scored**, and the count is
  reported. Adding a detector means adding it to that skip list too.
- Match existing style; don't reformat unrelated code.
- Conventional Commits for messages (see CONTRIBUTING.md).
- `CHANGELOG.md` is generated by release-please — don't hand-edit it.

## Tooling

The GitHub workflows, `.pre-commit-config.yaml`, `.editorconfig` and
`SECURITY.md` are shared config, kept identical across the portfolio. A local
edit here is drift and the next sync overwrites it.

- Hooks are pinned by commit SHA with the tag in a trailing comment. A tag can
  be moved, a SHA cannot.
- `pre-commit install` once per clone. Don't add a `.githooks/` directory:
  `core.hooksPath` replaces `.git/hooks/` wholesale, so setting it silently
  stops every pre-commit hook from running.
- CI runs this same `.pre-commit-config.yaml` through `pre-commit/action`, so
  what passes locally is what gates the pull request.

## Releases

release-please runs in **manifest mode**: `release-please-config.json` lists
every file that carries the version, so merging the release PR moves
`version.txt`, `CHANGELOG.md`, both `pyproject.toml` files and both module
`VERSION` constants together. A version string added anywhere else needs an
`x-release-please-version` annotation on its line and an entry in
`extra-files`, or it will silently drift from the tag.

The first release was pinned to 0.1.0 with `release-as`, because release-please
defaults an untagged repo to 1.0.0. That pin is gone now that `v0.1.0` exists —
left in place it would have pinned every later release to the same number
and stopped `feat:` bumping anything. Versions are ordinary semver from
here: `fix:` patch, `feat:` minor, and while this is 0.x a breaking change
does not need a major bump.

## Guardrails

- Don't add dependencies. Zero is the number, in both packages.
- Don't merge the two tools. They answer different questions and are useful
  separately; the shared folder is documentation, not coupling.
- `gradebook-code` rates `gradebook-tests` a **D** (53/100), mostly for being
  one 2,277-line god file with 16 functions past the complexity limit. It is
  right, and `docs/gradebook-code.md` says so — don't quietly drop that
  admission while refactoring.
- Ask before large refactors or destructive operations.
